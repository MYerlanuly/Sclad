# Склад на сервере: установка один раз, обновление одной командой

Это основная инструкция. Подходит и для Windows-, и для Linux-сервера во внутренней сети.
Остальные файлы в `docs/` (DEPLOY_LINUX, DEPLOY_DEBIAN_NGINX, DEPLOY_OFFLINE) описывают
ручную настройку и nginx, они нужны только если хочется сделать иначе.

## Как это устроено

На сервере лежит git-клон репозитория. Склад работает как служба и сам стартует
при включении сервера. Чтобы поставить новую версию, достаточно запустить
`update.bat` (Windows) или `sudo ./update.sh` (Linux). Скрипт обновления:

1. делает копию базы каждого склада в `backups/before-update/` (хранятся последние 15);
2. скачивает новую версию кода (`git pull`);
3. ставит зависимости из `requirements.txt`;
4. обновляет схему базы каждого склада (миграции);
5. перезапускает службы складов и проверяет, что сайт открывается.

Если после обновления что-то сломалось, откат одной командой (см. ниже).

Рабочие данные (`*.db`, `.env`, `backups/`, `logs/`) в git не попадают, поэтому обновление
их не трогает.

## Windows-сервер

Нужно: Windows 10/11 или Windows Server, права администратора,
[Python 3.13](https://www.python.org/downloads/) (при установке поставьте галочку
«Add python.exe to PATH») и [Git for Windows](https://git-scm.com/download/win).

### Установка (один раз)

1. Откройте командную строку и скачайте проект, например в `C:\sclad`:

   ```bat
   cd C:\
   git clone https://github.com/MYerlanuly/Sclad.git sclad
   ```

2. Если склад уже работал на другом компьютере, скопируйте его `inventory.db`
   (и базы других отделов, и их файлы `.env.<код>`) в `C:\sclad`.

3. Дважды щёлкните `C:\sclad\scripts\windows\install.bat` и разрешите запуск от администратора.
   Скрипт сам создаст окружение Python, файл `.env` с секретным ключом, базу (если её нет,
   спросит логин и пароль администратора), службу с автозапуском и правило в брандмауэре.

В конце он покажет адрес, например `http://SERVER01:5000`. Его открывают с любого
компьютера в сети.

Склад другого отдела ставится так же, со своим файлом настроек
(см. [MULTIPLE_WAREHOUSES.md](MULTIPLE_WAREHOUSES.md)):

```bat
cd C:\sclad
copy .env.otdel.example .env.otdel2
notepad .env.otdel2
scripts\windows\install.bat .env.otdel2
```

Служба — это задача «Sclad» (у отделов «Sclad-<код>») в Планировщике заданий: запускается
при старте Windows от имени SYSTEM и перезапускается при сбое. Журнал сайта: `C:\sclad\logs\`.
Порт задаётся `SCLAD_PORT` в `.env` (по умолчанию 5000). Если поставить `SCLAD_PORT=80`,
адрес будет без порта: `http://SERVER01`; после смены порта запустите `install.bat` ещё раз.

### Обновление

Дважды щёлкните `C:\sclad\update.bat` и разрешите запуск от администратора. Всё.

## Linux-сервер (Debian / Ubuntu)

### Установка (один раз)

```bash
sudo apt install -y git
sudo git clone https://github.com/MYerlanuly/Sclad.git /opt/sclad
cd /opt/sclad
sudo scripts/linux/install.sh
```

Перенос существующей базы: перед `install.sh` положите `inventory.db` в `/opt/sclad`.

Скрипт поставит Python, создаст окружение, `.env` с секретным ключом, базу и администратора
(если базы нет), службу systemd `sclad` (gunicorn) и в конце покажет адрес вида
`http://192.168.1.10:5000`. Склад работает от пользователя `www-data`.

Другой отдел: `sudo scripts/linux/install.sh .env.otdel2` (служба `sclad-otdel2`).

Если нужен адрес без порта и HTTPS, поставьте перед складом nginx по
[DEPLOY_DEBIAN_NGINX.md](DEPLOY_DEBIAN_NGINX.md), а в службе замените `0.0.0.0` на `127.0.0.1`.

### Обновление

```bash
cd /opt/sclad
sudo ./update.sh
```

Журнал службы: `journalctl -u sclad -n 50`.

## Если после обновления что-то не так

| Что сделать | Windows | Linux |
|---|---|---|
| Вернуть прошлую версию кода (данные остаются) | `update.bat --rollback` | `sudo ./update.sh --rollback` |
| Вернуть и код, и базы на момент обновления | `update.bat --rollback --restore-db` | `sudo ./update.sh --rollback --restore-db` |

Второй вариант теряет всё, что внесли в склад после обновления, поэтому он спрашивает
подтверждение и перед возвратом ещё раз сохраняет текущие базы в `backups/before-update/`.
Обычно хватает первого: миграции только добавляют таблицы и поля, старый код с ними работает.

Откат действует до следующего обновления: следующий `update` снова поставит последнюю версию,
поэтому запускайте его, когда ошибка исправлена.

Возможные сообщения скрипта обновления:

- **«есть изменённые вручную файлы»** — на сервере кто-то правил код. Посмотрите `git diff`;
  если правки не нужны, выполните `git checkout -- .` и запустите обновление снова.
- **«git pull не удался»** — с сервера нет доступа к GitHub. Если репозиторий закрытый,
  один раз сохраните на сервере токен только для чтения:
  `git remote set-url origin https://<токен>@github.com/MYerlanuly/Sclad.git`.
- **«сайт не ответил»** — смотрите журнал (`logs\` на Windows, `journalctl -u sclad` на Linux).

## Сервер без интернета

1. На компьютере с интернетом в папке проекта:
   `pip download -r requirements.txt -d wheels --platform <win_amd64 или manylinux2014_x86_64> --only-binary=:all: --python-version 3.13`
   и `python scripts/download_offline_assets.py`.
2. Перенесите на сервер новую версию файлов проекта вместе с папкой `wheels/`
   (поверх старых; `*.db`, `.env`, `backups/` не трогайте).
3. Запустите `update.bat --no-pull` или `sudo ./update.sh --no-pull`: скрипт сделает копии баз,
   поставит пакеты из `wheels/`, обновит схему и перезапустит склад.
